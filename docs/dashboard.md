# Business overview dashboard — 3 November 2026

The local preview at http://localhost:8091 now opens with four KPI cards (completed sales in GBP, invoice count, invoice AOV, distinct identified purchasing customers) and four charts (monthly sales, top five countries, top five product/line codes by sales, and RFM segments). The existing AI question form, result table/chart, history and evidence remain below the overview.

## Meaning and shared filters

Date and country controls are shared by all overview sections. Date ranges include the selected end date through a half-open next-day timestamp boundary. All-data mode uses the manifest's observed bounds. Completely unavailable date ranges and countries outside the loaded dataset are rejected. Changing a control hides the previous overview until the user updates it, so stale totals are not displayed under new filters; controls are disabled while an overview request is running.

The AI form receives the same selected period and country. An explicit period in the question continues to take precedence, with the resolved scope displayed. A selected country is enforced at the SQL execution boundary on each base transaction scope; omitting it or bypassing it with OR is rejected. Arbitrary snapshot SQL with a country selector is rejected: use the dashboard's verified cohort instead. This narrow check does not certify general SQL equivalence.

Completed sales and invoice AOV use `orders`, including anonymous invoices. Distinct customers exclude null customer IDs. Product ranking uses sale lines joined to consistent invoices in the selected scope; source codes include special entries such as manual charges and postage, which the page explicitly labels. Sales are gross completed sales before returns, not profit or net sales.

RFM counts are **not recalculated snapshots**. They include only identified purchasers in the selected time/country scope who also have a record in the existing `2011-12-01` snapshot. The snapshot date and cohort definition are visible below the graph. RFM totals can therefore be lower than the purchasing-customer KPI. Historical boundary months can be incomplete, as shown by the manifest's observed dates.

## Execution and evidence

Overview SQL is a small application-owned set of read-only queries with validated controls; it is not generated by the language model and does not pretend to be an agent answer. Each section passes the existing SQL AST guard, OPA pre-authorization, bounded Spark execution, result contracts and OPA post-authorization. The AI path retains mandatory RAG and its existing semantic/reviewer checks.

The overview caches at most 32 scope results for five minutes within the current app/build. Cached numeric results still require current OPA authorization before being returned; a denied or unavailable policy never falls back to serving cached results. The web lock serializes overview and AI Spark work. No package, external chart service, ETL rebuild or remote publication was added.

Expandable overview details show the build ID, exact scope, SQL and policy/contract outcomes. The AI result now also has a visible list of recorded agent events. These are the **completed events of the latest answer**, not a simulated live-progress animation or a new event-streaming backend.
