# การจัดบริบทของ Agent

RAG ใช้ BM25 และคำศัพท์สองภาษา ค้น 6 อันดับแรก แล้วเติมนโยบายและหลักฐานที่ต้องใช้ Agent เก็บข้อความหลักฐานครบ ส่วนคะแนนค้นหาและ hash อยู่ใน trace เมื่อแก้ SQL จะเก็บคำถาม หลักฐานเดิม และ SQL กับข้อผิดพลาดล่าสุด

การทดลองควบคุมใช้ 12 คำถามในสามสภาวะ รวม 36 รอบ ทุกสภาวะใช้ RAG ชุดตัดข้อความรบกวนได้ 12/12 ส่วนชุดที่เก็บข้อความรบกวนทั้งหมดได้ 10/12 อีกสองข้อหยุดที่งบ context ผลครอบคลุมข้อความประกอบที่ทดสอบ [หลักฐานรอบทดลอง](../reports/CONTEXT_REPORT.md)

## การตรวจงบ context

จาก trace เว็บ 103 รายการ มี 119 ครั้งที่มีทั้งค่าประมาณและจำนวน token ที่ Ollama รายงาน มัธยฐานค่าประมาณสูงกว่าค่าจริง 2.49 เท่าตอนสร้าง SQL, 2.43 เท่าตอนตรวจ และ 2.47 เท่าตอนแก้ ค่าสูงสุดที่วัดได้คือ 2,771 tokens

คำถามดูรายชื่อคอลัมน์รองรับรูป “คอลัมป์” และ “คอมลัมป์” ในประโยคขอดู schema โดยอ่านชื่อและชนิดคอลัมน์จากตารางที่โหลดไว้ ใช้ RAG อ้างอิง schema และเรียกโมเดล 0 ครั้ง

Agent เลือก context 8,192 tokens เมื่องบ input โดยประมาณไม่เกิน 6,000 และขยายเป็น 16,384 tokens สำหรับ prompt ที่ต้องใช้งบประมาณสูงขึ้นถึง 14,000 ค่าประมาณรวมคำถาม คำสั่งระบบ schema หลักฐาน RAG และข้อมูลที่แนบตอนแก้ SQL หน้าเว็บรับคำถามได้ถึง 4,000 ตัวอักษร ใน trace ดู `estimated_input_tokens`, `context_window` และ `prompt_eval_count` เพื่อแยกค่าประมาณออกจากจำนวนที่ Ollama รายงาน

ทดสอบผ่านเว็บ MCP และ Spark ด้วยคำถามนับออเดอร์เดือนมกราคม 2011 คำถามสั้นใช้ context 8,192 ส่วนคำถามที่เพิ่มคำอธิบายเงื่อนไขจนยาว 3,456 ตัวอักษรใช้ context 16,384 ตอนสร้าง SQL ระบบประเมิน 10,015 tokens และ Ollama รายงาน 2,761 ทั้งสองแบบคืน 1,086 ออเดอร์
